# Independent security review

Reviewed the working-tree rules snapshot on 2026-11-03 while implementation was actively changing. Line numbers refer to that snapshot and may move. Findings below were reported to the implementation and rules agents; they are not a claim that the current tree still contains them.

1. **Approval bypass, confirmed** — `firestore.rules:422-427`: an event owner could edit `notes` (purpose) on an approval-required event because the material-fields list omitted it. The owner could also change `configSnapshot.approval` from `required` to `immediate`, then change its date/audience without a new request. Verification: seed an approval-required event owned by an officer; require both writes to fail unless an atomic approved replacement request matches the exact final event. Include snapshot removal and legacy events in tests.
2. **Private draft disclosure, confirmed** — `firestore.rules:209-211`: `allow read: if active()` exposed unpublished minutes drafts to unrelated active members. Verify direct reads and collection listeners fail for ordinary non-editor members but work for the designated editor and authorized administrators; room subscriptions must not expose the draft.
3. **Handoff and editing authorization** — `firestore.rules:156-157,176-183,211`: a host/cohost could change `hostUid`, `cohostUids`, and `minutesUid` without constraining the target or atomically updating session/draft; `meetingEditor` also allowed any administrator to edit draft content. Verify only authorized handoff targets succeed, meeting and session/draft revisions advance atomically, stale/offline writes cannot restore an earlier host/editor, and administrator publication does not grant ordinary draft editing.
4. **Cross-term subcollection writes** — `firestore.rules:198-207,245-266`: `termOk()` checks only the incoming document's term, without requiring that the parent meeting belongs to the current term. A current editor or host of an old live/prepared meeting could submit a document stamped with the current term. Verify direct writes to old-term agenda, contributions, attendance, sensitive records, session and minutes all fail even when payload `termId` is current.

Evidence: an isolated `demo-terra-security-review` Firestore emulator project was loaded with the reviewed rules and seeded with a current active officer, an approval-required event, and another person's minutes draft. `assertSucceeds` confirmed the officer could change the event's purpose, downgrade its snapshot and change its date, and read the draft. Command executed with `FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 node --input-type=module` and `@firebase/rules-unit-testing`; all three assertions passed. The first sandboxed execution could not connect (`EPERM`); the authorized local-emulator execution completed successfully. No production services were contacted.
5. **Direct event creation bypass and excessive updates** — `firestore.rules:414-424`: omitting `configSnapshot` allowed creation of a non-meeting event even when the current term policy required approval. `isBoss()` granted secretary and treasurer access to another owner's event, and optional `revision` permitted a client to remove the field to bypass revision comparison. Verify direct legacy-shaped writes against required policy fail, secretary/treasurer cannot edit or archive someone else's event, and revisioned event updates cannot remove or reuse a revision. Preserve read access to pre-existing legacy documents.

## Confirmation pass

Current working-tree rules were loaded in the local emulator on 2026-11-03. `FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 node --test tests/meeting-concurrency.test.mjs` produced **10 pass, 1 fail**. The passing tests cover private draft/topic/sensitive reads by room clients, stale editor writes, cross-term writes, teacher writes, and revocation of temporary task edits after closure. The failure reproduces disclosure of nested `attendance.reason` in a published version: the version rules bounded the list but did not validate its elements (`firestore.rules:267-286`; test `tests/meeting-concurrency.test.mjs:139`). The rules team was fixing this while the review ran.

A separate local project `demo-terra-term-read` directly confirmed that an active, uninvited new-term officer could read an old meeting's attendance and the old editor could read its private draft. The read rules for room subcollections and private drafts used active membership/old editor identity without checking current term or participant membership. This remains a blocker until authorized current-term and explicitly permitted historical reads are enforced and verified.

The current event update branch around `firestore.rules:548-552` also appeared to permit an immediate ordinary event to change type to a meeting while preserving its existing immediate snapshot, bypassing the default meeting approval; legacy snapshotless events have a similar material-change path. This was reported for a direct proof and fix. Rules and application code were actively changing during this pass, so these results do not certify the final integrated tree.


## Implementation resolution and final verification

The findings above describe intermediate reviewed snapshots. Confirmed findings were addressed in the implementation; see [final verification](upgrade-verification.md) for the 72 passing rules cases, 11 passing concurrency cases, focused browser corrections, and remaining configuration/production-smoke requirements. This resolution note is implementation evidence, not an additional Terra approval round.
